# 시간별 평가팩 사용법

새 시험에서 원하는 시간팩을 선택하고 모델·장비 연결을 확인해 시작합니다. 모델이 문제를 푸는 동안 성능을 함께 측정합니다.

| 시험 | 문항 수 | 용도 |
|---|---:|---|
| 간단 · 10분 | 54 | 연결·기본 능력·큰 품질 저하 확인 |
| 소형 · 1시간 | 259 | 주요 분야의 빠른 비교 |
| 상세 · 4시간 | 995 | 분야·난도별 차이 확인 |
| 전체 · 8시간 | 1,959 | 기존 7종에서 모든 평가 영역을 다루는 고정 발췌 |

작은 팩의 문항은 큰 팩에 모두 포함됩니다. 팩·버전·추론 설정·출력 한도가 같은 결과끼리 비교하세요. 원본 전 문항은 별도 평가팩으로 유지합니다.

## 시간과 추론 설정

시간 이름은 **단일 요청에서 추론 포함 전체 생성 60 tok/s**를 기준으로 한 구성 예산입니다. 생성에 90%, Prefill·통신 등 비생성 시간에 10%를 배분했습니다. 채점 대기는 포함하지 않습니다. 실제 종료 시간이나 시간 제한을 뜻하지 않습니다. 모델의 풀이 길이와 동시 처리에 따라 달라집니다. 제품 검증에서 Qwen은10분 팩54문항에20.27분이 걸렸습니다. 생성량이 기준의2.10배였으므로, 모델별 시간 보정은 계속 검증해야 합니다.

High가 지원되면 High를 기본 비교 조건으로 사용합니다. 지원되는 이름과 실제 적용값을 확인하세요. 이번 선별의 DeepSeek는 High, Qwen은 서버 기본 xhigh를 사용했습니다. 이름이 같아도 추론량이 동일하다는 의미는 아닙니다. Max는 별도 시험 조건으로 기록합니다.

출력 한도는 과도한 생성과 반복을 막는 안전 한도입니다. 팩의 목표 시간에 맞추려고 답변을 중간에 자르지 않습니다. length 종료는 별도 집계하며 한도를 높인 재시험은 기존 결과와 분리합니다. 자동 재시도에서 가장 잘한 답을 기존 Pass@1에 넣지 않습니다.

## 구성 근거와 한계

- 기존에 검증한 GSM8K·MATH-500·MMLU-Pro·BBH·IFEval·HumanEval·MBPP 팩의 입력·정답·채점 조건을 유지합니다. Math-Verify를 사용하는 MATH, 자체 답안 추출기를 사용하는 BBH, 실행 방식을 적용한 MBPP 등 공식 방식과의 차이는 원본 팩 고지에 기록합니다. 공식 점수와 완전히 같다고 표시하지 않습니다.
- 원본 SHA256을 검증한 뒤 고정 문항 ID로 구성합니다. 원본이 바뀌면 임의로 다른 문항을 대신 실행하지 않습니다.
- 분야·원본 난도·풀이량 구간·기존 정오답을 층화하고 고정 seed로 선택했습니다. 정답률을 원본과 같게 맞춘 구성이 아닙니다.
- 8시간 팩은 MMLU-Pro14개 분야와 BBH27개 유형을 모두 포함합니다. 작은 팩으로 세밀한 모델 순위를 단정하지 않습니다.
- 두 모델의 정상 완료 풀이량이 있으면 큰 값을 사용했고, 나머지는 DeepSeek 값을 사용했습니다. 미측정 모델의 소요 시간을 보장하지 않습니다.
- 잘림448개, 추출 미확정373개, 원자료 결함5개는 이번 목록에서 보류/제외했습니다. 긴 정상 풀이와 정상 오답은 포함합니다. 진단 결과에 따라 다음 버전을 검토하며 실행 중 목록을 바꾸지 않습니다.
- 지능·성능·종합 점수의 기존 가중치는 변경하지 않았습니다. BBH는 기존 정책대로 별도 정확도입니다. 보고서의 미평가 범위와 팩 버전을 함께 확인하세요.

## 배포와 개인정보

문항 ID·원본 해시·구성 및 합계 비용만 manifest에 포함합니다. 개인 모델 답변·장비 기록·API 키는 포함하지 않습니다. 데이터 고지는 기존 `docs/THIRD-PARTY-NOTICES.md`와 원문 라이선스를 유지합니다. MBPP를 포함한 발췌·배열 변경을 이 문서와 manifest에 표시합니다. 이 팩은 공식 원본 전체 점수가 아닙니다.
