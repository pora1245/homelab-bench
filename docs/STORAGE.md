# 기록 저장과 실행 슬롯

문항은 `run_items`, 장비 표본은 `run_telemetry`에 별도로 저장합니다. 장비 표본은 실행 ID와 순번으로 보존하며 새로 수집한 표본만 추가합니다. 매 문항 저장 때 이전 장비 이력을 다시 직렬화하거나 덮어쓰지 않습니다.

이전 버전의 인라인 장비 이력은 시작 시 트랜잭션으로 이관합니다. 기존 문항 행은 다시 쓰지 않으며, 휴지통 이력도 함께 처리합니다. 이관 실패 시 원래 저장 상태를 유지합니다. 이전 버전으로 되돌려야 한다면 실행기와 이관 전 데이터베이스 백업을 함께 복원해야 합니다.

시험 현황은 최근 장비 표본 300개와 전체 표본 수를 받습니다. 전체 보고서·내보내기는 전체 이력을 사용합니다. 보고서는 최초 전체 이력을 받은 뒤 순번 기준 증분을 받아 중복 전송을 줄입니다. `GET /api/runs/{id}/telemetry?after=순번`은 해당 순번부터 끝까지 반환하며 `telemetry_count`는 전체 수입니다.

생성과 채점은 별도 작업으로 실행합니다. 생성 동시 수는 시험 설정을 따르고, 채점은 동시에 최대 4개, 채점 전후 대기 답변은 최대 64개로 제한합니다. 대기 상한에 도달하면 채점이 따라올 때까지 생성 배정을 잠시 멈춥니다. 일시정지는 진행 중 생성과 채점을 마친 뒤 완료됩니다. 이 보호 상한 때문에 채점이 무한히 느린 경우까지 생성 속도를 유지하는 것은 아닙니다.
