# 기존 벤치 기반 시간별 평가팩 배포 계획

상태: **Qwen 네 모드 실측 시간 보정 완료 · 기본팩 `2026-11-09.1` 확정 · Mac·Windows 실행 번들 검증 범위 기록 완료**

## 최신 확정 · 2026-11-09

기본팩 하나의10분·1시간·4시간·8시간 모드를41·160·536·1,010문항으로 확정했다. Qwen3.8 Flash IQ3·RTX3060·단일 요청·기본 추론(xhigh)의 첫 회차 전체 요청 시간은10분22.5초·1시간1분5.5초·4시간16분14.4초·8시간8분56.8초다. 모두 사용자가 승인한±20%를 통과했다. 10분은 단독3회 중앙값(범위9분21.9초~11분32.4초), 나머지는 단독1회다. 최종 문항에 추정 시간을 섞지 않았다.

시간 보정은 추론을 포함한 실제 요청 시간으로 판단하며 채점 대기와 진단 재시험은 제외한다. 계측이 완전한 출력 실패도 첫 회차 전체 소요시간에는 포함하고, 정상 출력이나 정상 성능 표본으로 취급하지 않는다. 요청·채점환경 오류와 계측 누락은 시간 통과를 막는다. 4시간 원본 출력 실패2건·8시간4건 및 같은 설정1회 진단은 별도로 보존했고, 긴 두 모드의 출력 완결성은 미통과다. 원점수를 덮거나 실패 문항을 삭제해 시간을 맞추지 않았다.

최종 ID·원문 해시·출처 해시와 모드별 문항 순서를 고정했다. 하위 모드의 문항은 상위 모드에 포함되며,8시간은 MATH35개 분야·난도 조합·MMLU14개 분야·BBH27개 유형·IFEval24개 지시 ID를 포함한다. 상세 실측과 실패는 [기본 벤치팩](BASIC-PACK.md)에 기록한다. 이 확정은 시간 보정과 구성의 확정이며, 모든 운영체제의 신규 설치 검증 완료를 뜻하지 않는다.

## 이전 결정과 초기 후보 이력

2026-11-08에 사용자가 시간 오차±20%를 승인했다. 기존10분41문항과1시간160문항 실측을 재사용하고4시간·8시간 실측으로 이어갔다. 이전±3% 반복 조건과 초기 후보의 추정 비용은 과거 이력이다. 출력 완결성과 전체 요청 시간은 위 최신 기준에 따라 구분한다.

이전 정정(2026-11-08): Qwen 약60 tok/s 조건에서 실제 요청시간을 측정해, 길면 문항을 빼고 짧으면 추가한다. 10분·1시간의 가감·재측정을 먼저 끝낸 후4시간·8시간을 보정한다. 그 다음 하나의 기본팩으로 확정한다. 이전 v2의43·160·536·1,010문항은 임시 후보이고 아래 v1은 과거 이력이다. 정본: `evidence/qwen-time-calibration-20261108/REPORT.md`.

사용자 최신 목표는 **10분·1시간·4시간·8시간 벤치로 압축하고 불필요한 전체 분량을 줄이는 것**이다. 8시간을 모든 분야를 다루는 전체 벤치로 두고, 원본 전 문항은 선별·검증용으로 보존하는 안을 검토한다. 2026-11-08 사용자 실행 지시에 따라 채점 정정과 진단용 후보 시험을 시작했다. 시간팩 v1은 54·259·995·1,959문항으로 고정했다. 추가 진단 결과를 기다리지 않고 기존 유효 기록으로 구성했다. 근거와 채점 문제는 [실측 분석 보고서](../evidence/timed-pack-analysis-20261108/REPORT.md)에 기록했다.

DeepSeek 품질 21,567문항의 생성량은 60 tok/s 환산 65.12시간이다. MMLU-Pro와 BBH가 문항의 85.98%를 차지하므로 반복 분량 축소를 우선한다. Qwen은 부분 완료이고 과목별 1,000문항 임시 제한이 있어 단순히 기다려도 모든 분야의 공통 비교 자료가 확보되지는 않는다. BBH 일부 형식 오채점도 정정·검증해야 한다.

## 배포 목표와 출제 의도

현재 들어 있는 공개 벤치7종을 선별해 **하나의 기본팩에10분·1시간·4시간·8시간 전체** 네 모드로 제공한다. 신규 데이터셋과 자체 제작 문항은 이번 범위에 추가하지 않는다. 사용자는 팩을 선택해 모델의 정확성, 지시 준수, 문제 해결 능력과 실제 처리 성능을 확인한다.

각 문항은 기본 능력 확인, 능력 차이 확인, 어려운 조건에서의 한계 확인 중 어떤 역할을 맡는지 기록한다. 쉬운 문항도 기본 동작을 확인하는 기준으로 유지하며, 어려운 문항은 채점이 올바르고 평가하려는 능력이 명확한 경우에 사용한다. 현재 자체 한국어 문항과 기존 성능 전용13문항은 기본팩의 네 모드에 포함하지 않는다. TTFT·Decode·Throughput 등 성능은 품질 문항을 푸는 동안 측정한다.

확인된 BBH 형식 오채점 8건과 원자료 결함 5건부터 검토한다. 형식 오채점은 정답 추출을 고쳐 해결할 문제이며 해당 유형 전체를 버리는 근거가 아니다. 코드 채점 환경 실패는 모델의 코드 오답과 분리한다. 해결되지 않은 채점 오류를 0점으로 바꿔 배포하지 않는다.

## 시간별 문항 구성 방법

1. **후보 목록 고정:** 기존 원본 revision과 현재 시험 자료를 기준 시점으로 묶고 문항별 입력·정답 해시를 기록한다.
2. **유효성 정리:** 원자료 결함·완전 중복·채점 오류를 분류한다. 정상 오답과 출력 잘림은 별도 표식으로 유지한다.
3. **출제 유형 분류:** 위 표의 원본 메타데이터를 우선 사용하고, 없는 유형은 원문·해설·테스트에서 근거를 남겨 분류한다. 검증되지 않은 자동 분류는 확정 분류와 구분한다.
4. **비용표 작성:** 추론 포함 생성량과 단일 요청 비생성 시간을 구분한다. 두 모델 자료가 있으면 큰 생성량을 초기 비용으로 참고하고, 한 모델만 있으면 비용 검증 대기로 표시한다. 채점 대기는 모델 풀이 예산에서 제외한다.
5. **중첩 선별:** 10분 팩에 여섯 평가 영역의 기본 대표 문제를 배치하고, 1시간·4시간·8시간 순서로 분야·하위 유형·난도·풀이 길이의 범위를 넓힌다. 큰 팩은 작은 팩의 문항을 포함한다. 각 단계에서 추가할 유형의 예산을 먼저 남겨 작은 팩이 전체 예산을 소진하지 않게 한다.
6. **반복 감축:** 예산을 넘으면 이미 충분히 대표된 유형의 반복부터 줄인다. 짧은 문제순 또는 정답률순으로만 자르지 않는다. 검증된 하위 유형을 모두 담는 데 필요한 최소 비용이 8시간 예산을 넘으면 구성 충돌로 기록하고 범위·시간을 재검토한다.
7. **안정성 검토:** 저장된 유효 답변으로 원본과 발췌판의 분야별 정확도 차이, 유형 누락, 선정 seed에 따른 변동, 예상 풀이량을 비교한다. 일부 완료 자료는 해당 공통 범위에서만 비교한다. 점수를 원본과 같게 맞추려고 문항을 반복 교체하지 않는다.
8. **배포 목록 고정:** seed·정렬 규칙·문항 ID·포함/제외 사유·출처·채점기 버전·출력 한도를 manifest에 저장한다. 실행 중 모델 성적에 따라 문항을 교체하지 않는다.

문항 수는 시간 비용표 합산과 층화 선별로 결정했다. 10분 팩은 기본 확인용으로, 모든 하위 유형과 세밀한 순위 판별까지 요구하지 않는다. 8시간 전체는 기존 여섯 영역을 포괄하는 발췌판이며, 원본 전 문항과 구분한다. 기준 시간과 실제 예상 완료시간도 구분해 표시한다.

## 배포 전 완료 조건

- 기본팩 네 모드의 실제 문항 목록·문항 수·유형별 분포·시간 예산을 확정하고 중첩 관계와 모드별 실행 순서를 검증한다.
- BBH의 답안 단독 출력·결론 표현·괄호·정렬 답안을 포함해 정답과 오답 추출을 모두 검증한다. 저장된 답변을 재채점할 때 이전 판정을 보존한다.
- 채점 가능한 모든 포함 문항에 대해 정답 예시와 오답 예시를 검사한다. 정답을 알아야만 답안을 추출하는 규칙을 사용하지 않는다.
- 코드 채점기는 지원 환경에서 동작을 확인한다. 채점기 미설치 시 코드 과목 준비 상태와 누락 범위를 명시하며, 이를 완전한 전체 팩 결과로 표시하지 않는다.
- 새 시험 시작·진행·중단 후 복구·결과 저장·보고서까지 10분 팩으로 제품 경로를 검증한다. 긴 팩은 같은 실행기의 문항 처리·복구 경로와 목록/예산을 검증하고, 실제 시간 검증 범위를 기록한다.
- 고정 manifest에 따른 과목별 결과를 표시하고 팩 이름·버전·채점 범위·잘림·오류를 보고서에 남긴다. 기존 점수 가중치는 별도 승인 없이 바꾸지 않는다. 서로 다른 팩의 점수를 동일 시험 성적으로 취급하지 않는다.
- 포함 데이터·정답·테스트·채점기의 기존 라이선스와 고지 파일을 문항 출처별로 확인한다. 재배포가 확인된 파일만 번들에 넣고, 다운로드가 필요한 자료는 설치 경로와 조건을 기록한다.
- 배포 번들에는 프로그램·평가팩 manifest·허용된 데이터·한국어 사용법·출처 및 고지를 포함한다. 사용자 시험 원문·장비 기록·API 키는 포함하지 않는다.

다른 모델을 추가로 돌려 검증하는 작업은 후속 정확도 개선으로 남긴다. 이번 베타는 현재 확보된 자료로 선정하고 검증 범위를 공개한다. 현재 진행 중인 시험을 모두 다시 실행하는 것을 배포의 선행 조건으로 두지 않는다.

## 기준 시간과 평가 목적

단일 요청 Decode **60 tok/s**, 추론 포함 전체 생성량을 기준으로 한다. 생성 90%·Prefill/API 등 10%를 초기 예산으로 제안한다. Qwen c1에서 관측된 비생성 시간은 60 tok/s 생성 시간의 9.03%였으며, 이 비율은 다른 모델의 보장치가 아니다. **채점·채점 큐 대기는 모델 풀이 예산에서 제외한다.** 일반 TTFT에는 추론 생성 시간이 포함될 수 있으므로 전체 생성 시간에 그대로 더하지 않는다.

| 분야 | 10분 | 1시간 | 4시간 | 8시간 전체 |
|---|---:|---:|---:|---:|
| 기본 수학 · GSM8K | 27초 | 2.7분 | 10.8분 | 21.6분 |
| 고난도 수학 · MATH-500 | 108초 | 10.8분 | 43.2분 | 86.4분 |
| 지식·추론 · MMLU-Pro | 135초 | 13.5분 | 54분 | 108분 |
| 복합 논리 · BBH | 81초 | 8.1분 | 32.4분 | 64.8분 |
| 지시 이행 · IFEval | 81초 | 8.1분 | 32.4분 | 64.8분 |

| 생성 소계 | 9분 | 54분 | 216분 | 432분 |

위 분야 비중은 생성 시간 배분 초안이며 지능점수 가중치와 별개다.

- 간단 시험: 기본 동작과 큰 품질 저하를 확인한다. 작은 점수 차이의 순위 판단에는 부족하다.
- 1시간 시험: 주요 능력의 빠른 모델·설정 비교에 사용한다.
- 4시간 시험: 분야별 차이를 상세하게 확인한다.
- 전체 시험: 모든 능력 분야를 다룬다. **원본 전 문항 시험과 다른 발췌 시험**이며 둘을 별도 표기한다.
- 추론 토큰을 포함한 전체 생성량을 시간 산정에 사용한다. 가시 답변 Decode만 있는 엔진은 추론 처리량을 같은 값으로 가정하지 않는다.
- 60 tok/s만으로 시간 상한을 보장할 수 없다. 공통 문항에서 Qwen 생성량은 DeepSeek의 1.89배였다. 모델별 풀이 길이·Prefill이 달라 실제 ETA는 별도로 계산한다. 시간 상한으로 중단하는 모드는 고정 발췌 팩과 별개이며 미평가 문항을 완료로 표시하지 않는다.
- v1 문항 수는 10분54·1시간259·4시간995·8시간1,959개다. 이전의801문항 제안은 사용하지 않는다.

## 오프라인 후보 분석

두 개 이상의 **문항이 포함된 시험 JSON 내보내기**를 준비한다. 목록 요약 JSON만으로는 분석할 수 없다.

```bash
python3 tools/analyze_item_budget.py run-deepseek.json run-qwen.json \
  --decode-tps 60 --output data/item-budget-review
```

파일을 읽어 분석만 하며 API 호출·재채점·평가팩 생성·진행 중 실행 변경은 하지 않는다. 출력 파일이 있으면 덮어쓰지 않는다.

- `budget-audit.json`: 모델별 안전한 실행 조건과 차이, 과목·채점기·출처별 정오답/오류 수, 응답 시간·토큰·채점 시간 통계, 모델 쌍별 공통 문항 결과.
- `item-candidates.csv`: 공통 문항 ID·분야·분류·각 실행 상태·시간·토큰 수. 프롬프트·모델 원문·정답 원문·API 키·접속 주소는 포함하지 않는다.
- 하나라도 진행 중이면 `provisional: true`이며, 공통으로 완료한 문항에 한해 초기 후보를 확인한다. 완료된 실행이라도 실패·미채점이 남아 있을 수 있다.
- `discordant_candidate`는 입력·정답·채점 조건이 일치하고 유효한 정오답이 다른 문항이다. 변별력 검증이 끝난 문항이라는 뜻은 아니다.
- `grading_ms`가 없는 과거 기록은 미수집으로 남긴다. 응답 종료와 채점 완료의 차이는 큐 대기를 포함할 수 있어 순수 채점 시간으로 대신하지 않는다.
- `decode_only_ms_at_reference`는 출력 토큰 ÷ 60으로 계산한 생성 시간이다. Prefill·통신·채점을 포함한 완료 예상시간으로 사용하지 않는다.
- 현재 두 모델의 구성·추론 설정·양자화·엔진이 달라서 점수 차이를 모델 가중치의 영향만으로 해석할 수 없다.


## 추론 설정과 출력 한도

- 기본 추론은 지원되는 경우 High를 우선한다. 제공자별 이름이 같아도 동일한 연산량을 뜻하지 않으므로, 요청값·엔진이 해석한 값·근거를 함께 기록한다. Max는 별도 선택 조건이다.
- 이번 기존 자료 비교에서는 실제 기준선을 유지한다. DeepSeek의 이미지 내 토크나이저 기본값은 thinking on/High다. Qwen의 실행 중 템플릿 기본값은 xhigh이며 high도 xhigh로 해석한다. Qwen을 임의로 medium으로 낮춰 비교하지 않는다.
- 출력 한도는 무한 반복과 과도한 생성의 안전 한도다. 10분·1시간·4시간·8시간 팩은 문항 구성을 줄여 만들며, 풀이를 중간에 끊어서 시간을 맞추지 않는다.
- 추론 토큰과 가시 답변 토큰을 합친 생성량을 비용표에 사용한다. API별 최대 토큰 인자의 적용 범위를 확인하고 실제 요청값과 finish_reason을 남긴다.
- 기존 DeepSeek의 length 종료 448건은 별도 진단 시험에서 한도를 2배로 늘린다. BBH는 4,096→8,192, 나머지는 실행 유효 한도 8,192→16,384. 우선 13건으로 요청·출력·종료 상태를 확인한 다음 나머지 435건으로 진행한다.
- 재시도는 원래 답변과 판정을 덮어쓰지 않는다. 재시도 중 가장 좋은 답을 골라 기존 Pass@1에 넣지 않으며, 처음 시험과 한도 확대 시험을 분리한다. 다시 잘리는 문항은 원인·시간·토큰량을 기록한 검토 대상으로 남긴다.
- API 오류, 채점 실패, 출력 잘림, 정상 오답은 별도로 집계한다. 추출이 불확실한 답변을 변별력 근거로 쓰지 않는다.

## 구현 진행 · 2026-11-08

1. BBH v5를 PC/Mac에 적용했다. 저장된 6,511개 BBH 답변을 검증해 형식 오판정 205건을 정정했고 정답→오답 회귀는 없었다. 기존 원문·추론·계측·설정 및 이전 판정을 보존했다. 정상 종료했지만 추출 미확정인 373건은 추가 검토 대상으로 분리했다.
2. 후보 선별 도구 `tools/prepare_screening.py`를 추가했다. 정상 오답, 두 모델 판정 차이, 복잡한 정상 정답, 기본 확인용 정답을 층화해 442개 후보를 구성했다. 이는 최종 시간팩이 아니다.
3. Qwen의 동일 문항·동일 채점 조건 완료 답변 239건을 재사용하고 미측정 후보 203건만 별도 시험으로 시작했다. 기존 전체 시험은 3,599개 답변을 보존한 상태로 일시정지했다.
4. DeepSeek 한도 확대 시험 13+435건은 준비됐지만, 모델이 내려가 있고 하네스의 활성 작업 잠금이 계속 갱신돼 적재 대기 중이다. 다른 작업을 강제로 종료하지 않는다.
5. 사용자 정정에 따라 후보·한도 확대 진단을 팩 구성의 선행 조건에서 분리했다. 기존 정상 기록으로 네 시간팩을 고정하고 제품 연결·실행 검증·베타 번들을 준비한다. 추가 결과는 후속 버전 검토에 사용한다.

## 시간팩 v1 제품 검증 결과 · 과거 이력

Windows54문항을 끝까지 실행해 요청오류·채점실패·출력잘림 모두0, 계측·수집기·일시정지/재개·보고서 PNG저장을 검증했다. Qwen의 실제생성67,420토큰은 기준32,111토큰의2.10배였고 실제20.27분이 걸렸다. 따라서10분팩의 실제10분 충족은 확인하지 못했다. 기준시간과 실제시간을 구분하고, 긴팩의 실제시간 검증은 미실행으로 남긴다. 구성·원문·기존성적을 보존한 채 후속비용보정자료로 사용한다.

GSM8K·코딩 의미유형 전수 수작업분류, 포함문항별 정답/오답예제의 전수 실행은 미완료이며 구조적 분류·채점기계약·저장답변감사로 검증한 범위를 정본에 표시했다. Qwen후보203개는102개완료지점에서재개했고, DeepSeek448개는활성하네스잠금으로대기한다. 이 추가검증을제품구현·번들작성의선행조건으로두지않는다.

## 최신 검증 범위와 남은 검토

기본팩의 모든 선택 문항은 Qwen에서 직접 실행했고 첫 회차 요청 계측을 확인했다. 기존 원본 문항·출력 한도·채점 규칙·점수가중치는 유지했다. GSM8K·코딩 의미 유형 전수 수작업 분류와 포함 문항별 정답·오답 예제 전수 실행은 여전히 미완료다. 원본 메타데이터·구조적 분류·채점기 계약·저장 답변 감사와 실제 실행으로 확인한 범위를 구분한다. 다른 모델의 모든 실행시간이나 원본 전체 점수와의 동등성을 보장하지 않는다.

실행 번들에는 최종 manifest와 한국어 안내를 반영했다. Mac 실행·소스 ZIP의 파일 감사, Mac 실행 번들의 빈 DB·독립 포트 및 실제 앱 API를 통한 네 모드 구성·GSM8K 4·18·37·62문항 순서 실행을 확인했다. Windows x86_64 ZIP은 기존 PC의 별도 추출 폴더·빈 데이터에서 루트 시작기로 상태 응답·웹 UI·네 모드 구성과 종료를 확인했다. 모델 API 호출은 0건이며, 원래 모델 실측을 다시 실행한 검증은 아니다. Windows 대상 Rust 의존성 고지 193개·빌더 고지 원문 23개를 포함했고, 앱 실행 파일은 Windows 시스템 DLL만 의존한다. 별도 새 OS·일반 채점 의존성 신규 설치·Linux·Intel Mac·macOS 서명과 공증은 확인하지 않았다. 기존 v1과 이전 시험 기록은 그대로 보존한다.
