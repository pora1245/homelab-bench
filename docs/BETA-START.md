# LLM Bench 비공개 베타 시작 안내

이 번들은 개인 PC에서 모델 API를 시험하고 결과를 보는 **테스터용 로컬 베타**입니다. 시험 기록과 결과는 설치한 기기에 저장되며 개발자 서버로 자동 업로드되지 않습니다. 문제는 사용자가 연결한 모델 API로 전송되고, 채점용 외부 API를 선택하면 채점에 필요한 문제·정답·답변도 해당 제공업체로 전송됩니다. 비용·토큰 사용량은 사용한 서비스 기준을 따릅니다. 설치나 앱 실행만으로 모델 시험을 자동 시작하지 않습니다.

**AI에게 설치를 맡기려면 [AI 설치 안내서](AI-INSTALL.md)를 읽고 진행하라고 요청하세요.** AI가 모델 실행 위치, 장비 수집기, 코드 채점기 선택을 질문하고 필요한 설치·연결·상태 확인을 수행합니다. 앱은 별도 처음 사용 준비 화면 없이 홈으로 열리며 설정은 연결 관리에서 변경합니다.

## 받을 파일

- `llm-bench-0.1.0-beta-macos-arm64.zip`: Apple Silicon Mac 실행 파일과 화면, 허용된 평가팩을 포함합니다. Rust·Node를 설치하지 않고 앱을 열 수 있습니다.
- `llm-bench-0.1.0-beta-source.zip`: Rust/React 원본과 잠금 파일, 같은 평가팩을 포함합니다. 빌드에는 Rust/Cargo·Node/npm이 필요합니다.
- `SHA256SUMS`: 압축파일 무결성 확인용입니다. 터미널에서 다운로드 폴더로 이동한 뒤 `shasum -a 256 -c SHA256SUMS`로 확인합니다.

현재 실행 ZIP은 **macOS Apple Silicon용**입니다. 동일 Mac에서 별도 폴더·빈 기록/연결·별도 포트로 압축 해제 후 실행을 확인했으며, 별도 물리 Mac의 신규 OS 설치 검증은 아직 하지 않았습니다. 실제 확인 OS는 macOS 26.5.2이며 바이너리의 최소 링크 타깃은 11.0입니다. 이전 macOS에서의 실제 동작과 앱 서명·Apple 공증은 아직 검증 완료가 아닙니다.

**Windows 실행기는 실제 개인 PC에서 기동·채점·빠른 시험·장비 수집을 확인했습니다.** 다만 일반 배포용 Windows 실행 ZIP과 다양한 신규 Windows 환경에서의 설치 검증은 아직 준비 단계입니다. 소스 ZIP에는 Windows 준비·시작·빌드 스크립트가 들어 있으며 [Windows 안내](WINDOWS-NATIVE-PREPARATION.md)를 따릅니다. Intel Mac·Linux 전체 앱의 신규 설치는 검증 완료로 표시하지 않습니다. GitHub의 Code → Download ZIP은 실행 파일이 없는 소스이므로 [README의 소스 빌드](../README.md#소스에서-빌드하기)가 먼저 필요합니다.

## 1. 앱 열기 · Apple Silicon Mac 실행 번들

1. 실행 ZIP 전체를 쓰기 가능한 폴더에 압축 해제합니다. 예: 문서 폴더의 `LLM Bench`.
2. `Start-LLM-Bench.command`를 실행합니다. 첫 실행에 필요한 일반 채점 의존성을 준비한 뒤 앱과 브라우저를 엽니다. 이미 준비된 버전과 자료가 있으면 다시 다운로드하지 않습니다. 직접 준비만 하려면 `Setup-Graders.command`를 실행합니다.
3. macOS가 미확인 개발자 앱 실행을 차단하면 받은 출처와 체크섬을 먼저 확인하고 본인이 시스템 설정의 실행 허용 여부를 결정합니다. 보안 설정을 일괄 해제하거나 quarantine을 자동 제거하는 스크립트는 제공하지 않습니다.
4. 브라우저의 `http://127.0.0.1:18760`에서 **연결 관리**를 열어 모델 API 주소·모델 ID·키와 시험 장비를 연결합니다. OpenAI 호환 Chat Completions 또는 Responses API 방식을 맞춘 뒤 시험과 보고서를 사용합니다. 다른 사용자의 연결·키·장비·시험 이력은 이 번들에 들어 있지 않습니다.

브라우저만 닫으면 실행기는 계속 실행됩니다. 실행 터미널에서 **Control-C**를 누르면 종료합니다. 터미널을 닫기 전에 진행 중 시험을 일시정지/중단하거나 완료를 기다려 주세요. 포트가 이미 사용 중이면 `BENCH_PORT=18762 ./Start-LLM-Bench.command`처럼 바꿔 실행할 수 있습니다.

## 2. 채점 환경 준비

설치 AI가 모델 실행 위치와 장비 수집기·코드 채점기 사용 여부를 질문합니다. 답변은 설치 구성으로 저장하며, 선택한 구성만 준비하고 실제 상태를 확인합니다. 코드 채점을 선택하지 않으면 종합 시험의 기본 과목에서 제외하고, 나중에 연결 관리에서 준비한 뒤 새 시험에 추가할 수 있습니다.

같은 PC는 앱의 내장 장비 수집을 사용합니다. 외부 모델은 해당 모델 서버에 별도 수집기를 설치합니다. 수집기 전용 패키지에는 모델·평가 자료·Python·Docker가 필요 없습니다. 상세 설치 파일과 인증 연결은 [장비 수집기 안내](DEVICE-COLLECTOR.md)에 있습니다. 모델 API 주소가 localhost여도 장비 위치를 추측하지 않으며 모델 연결에 지정한 장비만 사용합니다.

처음 실행할 때 일반 채점 환경을 준비하고 이후에는 준비된 환경을 확인합니다. `.venv`, Python 실행 파일, Docker 이미지, NLTK 데이터는 번들에 포함하지 않습니다. 준비가 실패해도 앱은 열리며 내장 채점기를 사용하는 팩부터 시험할 수 있습니다. 준비 단계를 건너뛰고 앱을 열려면 `BENCH_SKIP_SETUP=1 ./Start-LLM-Bench.command`를 사용합니다.

- **응답 사용성·GSM8K·MMLU-Pro·BBH**: 내장 채점기를 사용하므로 Python·Docker 없이 시작할 수 있습니다.
- **IFEval·MATH-500**: Python 3.11 이상과 지정 의존성이 필요하며 IFEval에는 NLTK 자료도 필요합니다. Python 3.11을 권장합니다.
- **HumanEval·MBPP**: Python 채점 환경과 실행 중인 Docker Desktop 또는 Colima가 필요합니다. 모델이 생성한 코드를 호스트 Python으로 직접 실행하는 대체 경로는 없습니다.

기존 Python 3.11 이상을 자동으로 찾습니다. Python 자체가 없으면 `Install-Python.command`가 [공식 Python 설치 페이지](https://www.python.org/downloads/release/python-31410/)를 열고 설치 후 재검색합니다. **Python 설치 화면의 조작은 현재 직접 해야 하는 단계**입니다. 설치를 나중에 하려면 안내에서 Enter를 눌러 내장 시험부터 사용할 수 있습니다. `Setup-Graders.command`는 번들 안에 `.venv`를 만들고 필요한 고정 직접 의존성과 NLTK 자료만 준비합니다. Python 명령이 다르면 다음처럼 지정합니다.

```bash
BENCH_SETUP_PYTHON=python3 ./Setup-Graders.command
```

**Docker는 코드 시험을 선택할 때만 사용하는 별도 선택 의존성**입니다. 일반 수학·지식·추론·지시 이행·성능 시험에는 필요하지 않습니다. 준비 도구는 Docker·가상머신을 자동 설치하지 않습니다. 기존 Docker Desktop 또는 Colima가 실행 중이면 `Setup-Code-Grader.command`로 코드 채점 이미지만 준비할 수 있습니다. 같은 수동 명령은 아래와 같습니다. 작은 Dockerfile만 빌드 문맥으로 보내며 개인 폴더는 전송하지 않습니다.

```bash
docker build -t llm-bench-code:py311 - < scorers/Dockerfile
```

시작 스크립트는 두 코드 채점기 모두 이 이미지를 사용합니다. 공식 Python base는 Dockerfile의 digest로 고정하며, 실제 실행 때 이미지 ID를 기록합니다. Python 직접 의존성은 고정돼 있지만 전이 의존성까지 완전한 플랫폼별 lock을 제공하는 단계는 아닙니다. 설치 시 인터넷 연결이 필요합니다. 설치 후 앱의 새 시험에서 **상태 다시 확인**을 누르고 **채점 준비 완료**를 확인합니다. 준비 필요/확인 실패는 원인 안내에 따라 해결합니다.

Windows AppContainer·Mac App Sandbox를 사용하는 네이티브 코드 채점 경로는 아직 구현·검증 완료가 아닙니다. 현재 코드 채점 경로를 OS 네이티브 sandbox라고 표시하지 않습니다. 준비된 코드 환경이 없는 경우 호스트에서 생성 코드를 직접 실행하지 않습니다.

## 3. 시험과 점수

새 시험에서 모델·평가팩·빠른/전체 시험을 고릅니다. 진행 중 문제와 답안, TTFT·Decode, 문항별 판정을 볼 수 있습니다. 결과 화면의 보고서 양식을 고른 뒤 저장할 수 있습니다.

기본 번들의 평가 자료는 다음과 같습니다.

| 평가팩 | 전체 | 빠른 |
|---|---:|---:|
| 수학 추론 · GSM8K | 1,319 | 50 |
| 고난도 수학 추론 · MATH-500 | 500 | 50 |
| 지식·추론 · MMLU-Pro | 12,032 | 100 |
| 복합 추론 · BBH | 6,511 | 54 |
| 지시 이행 · IFEval | 541 | 50 |
| 함수 구현 · HumanEval | 164 | 25 |
| 기초 프로그래밍 · MBPP | 500 | 25 |
| 신규 종합 시험 | **21,567** | **354** |

MATH-500·MMLU-Pro는 원문 권리 근거를 재확인한 뒤 기본 번들에 포함했습니다. LiveCodeBench 데이터는 권리 조건 검토가 남아 기본 번들에서 제외합니다. 코드 라이선스만으로 문제·테스트 데이터의 권리를 추정하지 않습니다. 설치된 7개 품질팩을 묶은 종합 시험과 개별 팩을 선택할 수 있습니다. API Experience 자료는 기존 기록·기준값·API 호환용으로 보관하며 신규 선택과 종합 시험에서는 제외합니다. 미설치 과목이 남아 있는 결과는 모든 과목을 완료한 점수로 표시하지 않습니다. BBH는 별도 복합 추론 정확도를 보여주며, 추가만으로 기존 v3 지능 점수의 고정 가중치를 바꾸지 않습니다. BBH 원본의 손상·모순 문항 5개는 보존하되 채점하지 않습니다. 전체 6,511개 중 채점 가능한 수는 최대 6,506개이며 빠른 54문항에는 제외 대상이 없습니다. 선택 문항 수와 실제 채점 가능한 범위는 화면과 보고서에서 구분합니다. BBH 프롬프트·채점 규약과 원본 결함은 `docs/BBH-PACK.md`에 설명합니다.

성능은 품질 문제를 푸는 동안 수집한 유효 TTFT 중앙값과 실제 병렬 출력량(가시 토큰 합계/생성 구간 합집합)을 GPT-6.1 Sol Low의 저장된 API 실측 기준과 비교합니다. 현재 동시 요청 구간에서 정상 완료한 응답의 유효 측정 쌍 1개부터 잠정 점수를 표시하고, 시험 완료 시 최종 점수로 표시합니다. 별도 성능 문항을 실행할 필요가 없습니다. 성능 점수는 상한이 없습니다. 지능·종합은 100점 만점이며 종합은 `100 × (지능/100)^0.7 × min(성능/1000, 1)^0.3`입니다. 비중은 제품 정책입니다. 평가를 하지 않은 영역에 점수를 만들어 넣지 않습니다. 입력·출력 길이와 동시 요청 수 등 측정 조건을 함께 표시합니다. 과거 고정 입력 시험과 품질 문제에서 수집한 사용성 비교는 측정 방식이 다릅니다.

API 사용성은 네트워크·서비스 대기·추론 시간을 포함합니다. 순수 GPU 속도나 서버 내부 Prefill을 측정한 수치가 아닙니다. 기준 모델보다 빠르다는 것과 답변이 더 정확하다는 것은 별도 평가입니다.

## 4. 자료 추가와 소스 빌드

데이터팩을 직접 추가하려면 앱의 평가팩 추가에서 `schemas/pack.schema.json` 형식의 JSON을 선택합니다. 사용자 평가팩·문항 ID에는 `custom:`처럼 고유 접두사를 사용합니다. 공식 평가팩의 예약 ID를 재사용해 공식 점수로 보이게 만드는 등록은 차단됩니다. 추가 자료의 사용·재배포 권리를 확인해야 합니다. 제공된 설치 도구는 먼저 계획만 확인할 수 있습니다.

```bash
python3 tools/import_full_datasets.py --dry-run
```

실제 추가 설치에는 `tools/import-requirements.txt`의 pyarrow가 필요합니다. 다운로드는 사용자가 명시적으로 `--download`를 지정할 때만 수행합니다. 기본 번들에서 제외한 로컬 전용 자료는 `--download --download-local-only`를 별도로 지정해야 합니다. 이 옵션이 해당 자료의 재배포 허가를 뜻하지 않습니다. 설치 후 앱을 다시 시작하면 새 팩을 읽습니다.

BBH는 별도 `tools/import_bbh.py`와 고정 원본 manifest를 동봉합니다. 기본 팩은 이미 들어 있으므로 다시 받을 필요가 없습니다. 원본부터 재구성하려면 `python3 tools/import_bbh.py --download`를 실행합니다. 원본 다운로드 캐시와 과거 공개 모델의 출력 전문은 번들에서 제외합니다.

Apple Silicon Mac용 **소스 ZIP**은 Rust/Cargo와 Node/npm 설치 후 ZIP 루트의 `Build-Source.command`를 실행해 빌드합니다. GitHub 소스 체크아웃에는 이 파일이 `packaging/`에 있으므로 그대로 실행하지 말고 [README의 루트 기준 빌드 명령](../README.md#소스에서-빌드하기)을 사용합니다. Windows는 저장소 루트에서 `powershell -NoProfile -File .\packaging\Build-Source-Windows.ps1`로 빌드한 뒤 `.\packaging\Start-LLM-Bench-Windows.cmd`로 실행합니다. 선택한 Rust 대상에 맞는 C/C++ 빌드 환경도 필요합니다. Cargo.lock/npm lock을 사용하며, 소스 변경 뒤에는 새 산출물·체크섬을 생성해 배포본을 구분합니다.

## 5. 기록과 공유

- Mac 기본 데이터 폴더: 번들 폴더 아래 `data/`
- Windows 시작 스크립트 기본 데이터 폴더: `%LOCALAPPDATA%\LLM-Bench\data`
- `BENCH_DATA_DIR` 또는 Windows의 `-DataDirectory`를 지정했다면 그 경로를 사용합니다.
- 시험 기록·연결·장비: 데이터 폴더의 `app.sqlite3`
- API 키: 같은 폴더의 `credentials.json` 별도 파일. Unix 권한을 제한하지만 OS 키체인은 아닙니다.
- NLTK 자료: 같은 폴더의 `nltk_data/`
- 업데이트: 실행기를 종료하고 실제 사용 중인 데이터 폴더 전체를 백업한 뒤 새 번들에서도 같은 기록 경로를 사용합니다. 실행 중 DB 파일을 단순 복사하지 않습니다.
