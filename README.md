# 홈랩 벤치 (Homelab Bench)

모델이 문제를 푸는 과정을 보면서 **답변 품질, 응답 속도, 장비 상태**를 확인하는 로컬 벤치마크 앱입니다. 결과는 지능·성능·종합 점수로 확인하고, 보고서를 이미지나 PDF로 저장할 수 있습니다.

## 기본 벤치팩

**기본 벤치팩에서 10분·1시간·4시간·8시간 중 시험 시간을 선택합니다.**

| 모드 | 문항 | 용도 | Qwen 3.8 fn (60 tok/s) 실측 |
|---|---:|---|---:|
| 10분 | 41 | 연결과 기본 능력 확인 | 10분22.5초 |
| 1시간 | 160 | 주요 능력 비교 | 1시간1분5.5초 |
| 4시간 | 536 | 분야별 상세 확인 | 4시간16분14.4초 |
| 8시간 | 1,010 | 기본팩 전체 평가 | 8시간8분56.8초 |

Qwen · RTX 3060 · 단일 요청 약 60 tok/s 기준으로 목표 시간의 ±20% 안에 들었습니다. 10분은 3회 중앙값, 나머지는 1회 측정값이며 모델과 추론 설정에 따라 소요 시간이 달라집니다.

[기본팩 구성·실측](docs/BASIC-PACK.md) · [원본 자료·채점 방식](datasets/README.md)

벤치 앱과 모델은 같은 PC 또는 서로 다른 장비에서 실행할 수 있습니다. 시험할 모델의 API를 준비한 뒤 연결하세요.

시험 기록과 결과는 **벤치 앱을 실행하는 기기에 저장**되며 개발자 서버로 자동 업로드되지 않습니다. 문제는 연결한 모델 API로 전송되고, 외부 채점 API를 선택하면 문제·정답·모델 답변도 해당 제공업체로 전송됩니다.

## AI에게 설치 요청하기

사용하는 AI에 이 저장소를 읽고 설치해 달라고 요청하세요. AI용 순서와 확인 기준은 **[AI 설치 안내서](docs/AI-INSTALL.md)**에 있습니다.

> 이 저장소의 `docs/AI-INSTALL.md`를 읽고 설치해줘. 모델 실행 위치, 장비 수집기와 코드 채점기 사용 여부를 먼저 물어보고, 내 선택에 맞춰 설치·연결 설정·상태 확인까지 진행해줘.

AI는 다음 세 가지를 질문합니다.

1. **시험할 모델은 이 PC에서 실행하나요, 외부 서버에서 실행하나요?** 클라우드 모델 API도 외부에 해당합니다.
2. **장비 사용률·온도·전력을 기록할 장비 수집기를 설치하시겠습니까?** 같은 PC는 내장 수집을 활성화하고, 외부 서버는 그 서버에 별도 수집기를 설치합니다.
3. **코딩 문제를 채점할 코드 채점기를 설치하시겠습니까?** 선택하면 필요한 Python 채점 환경과 Docker 실행 환경을 안내하고 준비합니다.

AI가 선택에 맞춰 설치·연결·채점 환경을 준비하고 상태를 확인합니다. 직접 조작해야 하는 설치 화면이나 인증 단계는 별도로 안내합니다. 설정은 나중에 **연결 관리**에서 바꿀 수 있습니다.

## 직접 설치하는 순서

1. **다운로드·빌드** — GitHub의 **Code → Download ZIP**으로 소스를 받아 압축을 풀고, 아래 [소스 빌드](#소스에서-빌드하기)를 진행합니다.
2. **앱 시작** — 운영체제에 맞는 시작 스크립트를 실행하면 필요한 일반 채점 의존성을 준비하고 브라우저를 엽니다. Python이 없으면 안내에 따라 설치한 뒤 다시 실행하세요.
3. **모델·장비 연결** — 연결 관리에서 모델 API를 저장하고 장비 수집과 코드 채점을 선택합니다.
4. **새 시험** — 시험 모드와 과목을 선택하고 시작합니다.
5. **결과 확인** — 홈에서 점수를 확인하고 보고서 양식을 골라 저장합니다.

### 시작 스크립트

| 환경 | 일반 채점 준비 | 앱 시작 |
|---|---|---|
| Apple Silicon Mac | `packaging/Setup-Graders.command` | `packaging/Start-Homelab-Bench.command` |
| Windows x86_64 | `packaging/Setup-Graders-Windows.cmd` | `packaging/Start-Homelab-Bench-Windows.cmd` |

Apple Silicon Mac과 Windows x86_64에서 실행을 확인했습니다. 새 OS의 의존성 설치, Intel Mac·Linux 전체 앱 설치, macOS 서명·공증은 미검증입니다.

시작한 터미널은 열어 두세요. **브라우저를 닫아도 시험은 계속됩니다.** 시험을 일시정지하거나 완료한 뒤 시작 터미널에서 `Ctrl+C`를 누르면 앱이 종료됩니다.

## 1. 모델과 장비 연결

### 모델이 실행되는 위치

**연결 관리**에서 모델이 실행되는 위치에 맞춰 설정합니다. ‘이 PC’는 **벤치 앱이 설치된 장비**를 뜻합니다.

| 선택 | 설정할 내용 |
|---|---|
| **벤치 앱과 같은 PC** | 모델 API를 등록하고, 장비 수집은 내장 수집을 사용합니다. 별도 수집기를 띄울 필요가 없습니다. |
| **다른 PC·서버** | 해당 모델 서버의 API 주소를 등록합니다. 하드웨어 상태도 보려면 **모델 서버에** 장비 수집기를 설치합니다. |
| **클라우드 API** | API 주소·키·모델 ID를 등록합니다. 서버에 수집기를 설치할 수 없다면 장비 수집을 끄고 시험할 수 있습니다. |

### 모델 API 저장

**연결 관리 → 모델 추가**에서 다음 값을 입력합니다.

| 항목 | 입력 예·설명 |
|---|---|
| 이름 | 목록에서 알아보기 쉬운 이름 |
| API 주소 | 같은 PC라면 예: `http://127.0.0.1:8000/v1`, 외부 서버라면 그 서버의 실제 주소 |
| API 방식 | 서버가 제공하는 **Chat Completions** 또는 **Responses** |
| 모델 ID | API 서버에 등록된 정확한 모델 이름 |
| API 키 | 인증이 필요한 서버에만 입력 |
| 실행 기본값 | 출력 토큰 한도, 동시 요청 수, Temperature·추론 설정 등 |
| 실행 장비 | 실제 모델이 돌아가는 장비를 지정; 게이트웨이 주소만 보고 자동 추정하지 않음 |

저장 후 **연결 확인**을 누릅니다. 저장한 연결과 기본값은 다음 시험에서도 사용합니다. 유료 API를 연결하면 제공업체의 사용 요금이 발생할 수 있습니다.

기본 벤치팩은 정답·규칙·공식 채점기로 채점합니다. **채점 모델 API**는 LLM 판정이 필요한 사용자 평가팩에서 선택합니다.

### 장비 수집기 연결

외부 서버의 사용률·온도·전력을 보려면 모델 서버의 OS와 CPU에 맞는 수집기를 준비합니다. **장비 수집기에는 Python·Docker가 필요 없습니다.**

| OS | 준비 | 시작 |
|---|---|---|
| Windows | `Setup-Device-Collector-Windows.cmd` | `Start-Device-Collector-Windows.cmd` |
| Mac | `Setup-Device-Collector.command` | `Start-Device-Collector.command` |
| Linux | `bash Setup-Device-Collector-Linux.sh` | `bash Start-Device-Collector-Linux.sh` |

스크립트는 `packaging/`에 있습니다. 서버의 LAN·Tailscale 주소를 지정해 실행한 뒤, **연결 관리 → 장비 추가**에 `collector-connection.json`의 주소와 `agent-token.txt`의 인증 키를 입력합니다. 이 키는 모델 API 키와 다릅니다. 장비 연결을 확인하고 모델의 실행 장비로 선택합니다. 설정 명령과 토큰 파일 위치는 [장비 수집기 안내](docs/DEVICE-COLLECTOR.md)를 참고하세요.

장비 연결이 없어도 모델 API 시험은 할 수 있습니다. 수집할 수 없는 값은 0으로 채우지 않고 **미수집**으로 표시합니다.

## 2. 채점 환경 준비

**연결 관리**에서 과목별 채점 환경을 준비하고 상태를 확인합니다.

| 평가 영역 | 필요한 환경 |
|---|---|
| GSM8K·MMLU-Pro·BBH | 앱 내장 채점기. Python·Docker 없이 사용 가능 |
| MATH-500·IFEval | Python 3.11 이상과 일반 채점 의존성. IFEval은 NLTK 자료도 필요 |
| HumanEval·MBPP·별도 설치한 LiveCodeBench | 일반 채점 환경과 실행 중인 Docker Linux 컨테이너 환경 |
| 장비 상태 수집 | 내장 수집 또는 별도 Rust 수집기. Python·Docker 불필요 |

일반 채점 준비 스크립트는 `.venv`와 필요한 의존성을 준비하고 이미 준비된 환경은 재사용합니다. Python 자체가 없다면 공식 설치 페이지를 안내하며 설치 화면은 사용자가 진행합니다. 일반 준비에 실패해도 내장 채점기로 가능한 과목부터 사용할 수 있습니다.

**Docker는 코드 시험을 할 때만 필요합니다.** Docker 환경을 설치·실행한 뒤 아래 스크립트로 코드 채점 이미지를 준비하고 앱에서 상태를 확인하세요.

- Windows: `packaging/Setup-Code-Grader-Windows.cmd`
- Mac: `packaging/Setup-Code-Grader.command`
- Linux: `bash packaging/Setup-Code-Grader-Linux.sh`

Docker는 별도로 설치하고 실행해야 합니다. 코드 채점은 파일·네트워크 접근과 실행 자원을 제한한 컨테이너에서 진행합니다.

## 3. 시험 실행과 실시간 확인

1. **새 시험**에서 저장한 모델을 고릅니다.
2. **기본 벤치팩**을 고르고 **10분 / 1시간 / 4시간 / 8시간**과 과목을 선택합니다. 다른 사용자팩은 해당 팩이 제공하는 실행 모드를 사용합니다.
3. 화면의 선택 문항 수와 실행 설정을 확인합니다. 성능은 품질 문제를 푸는 동안 함께 측정됩니다. 기본팩의 보정 시간과 직접 비교하려면 단일 요청을 사용하세요.
4. **채점 준비 완료**를 확인하고 시작합니다. **준비 필요**는 누락 환경, **확인 실패**는 상태 확인 오류입니다. 안내대로 준비한 뒤 **상태 다시 확인**을 누릅니다.
5. **시험 현황**에서 문제, 모델 답안, 정답·채점 기준, 문항별 정답/오답을 확인합니다. 문항별 판정은 접을 수 있고, **진행 따라가기**를 끄면 이전 문항을 볼 수 있습니다.
6. 필요하면 **일시정지**하거나 **중단**합니다. 원격 모델 서버가 이미 받은 요청을 즉시 멈출 수 있는지는 해당 API 구현에 따라 다릅니다.

동시작업은 **자동 선택**이 기본입니다. 시작 시 최대 10분 동안 같은 문항으로 단일·동시 요청을 비교해 설정을 고르고, 본시험 처리량이 악화되면 이전 설정으로 복구합니다. 동시 수를 직접 지정할 수도 있습니다.

시험 중 TTFT·Decode·Prefill·Throughput과 장비 상태를 기록하고, 측정값으로 점수를 자동 계산합니다.

## 4. 점수와 보고서 읽기

홈에서 시험 기록을 선택하면 **그 기록의 점수와 결론**을 보여줍니다.

| 점수 | 의미 |
|---|---|
| **지능 /100** | 고정 평가 영역의 답안 품질을 합성한 점수 |
| **성능 · 상한 없음** | **GPT-6.1 Sol Low API 실측 = 1,000점**으로 둔 응답 경험 지수 |
| **종합 /100** | 지능 70%·기준 대비 성능 30%의 기하평균. 기준 이상의 성능은 종합 계산에서 만점으로 처리 |

성능은 **단일 요청의 가시 Decode·TTFT 기본점수 + 같은 표본으로 검증한 동시 처리 가산점**입니다. 기존 단일 측정 이력도 사용하므로 동시작업으로 전환해도 기본점수가 떨어지지 않습니다. 통신·서비스 대기·추론을 포함한 실제 API 사용 경험이므로 순수 GPU 연산 성능 순위와는 다릅니다. Prefill은 서버가 제공한 경우만 표시합니다.

**범위**는 평가하지 않은 지능 영역이 남아 있다는 뜻이고, **미산출**은 필요한 측정값이 없다는 뜻입니다. 기본팩에 없는 LiveCodeBench 때문에 지능·종합이 범위로 표시될 수 있습니다. 빈 응답·요청 오류·출력 잘림은 성능 계산에서 제외합니다.

앱의 합성 점수는 공식 벤치마크 리더보드 점수가 아닙니다. 세부 산식·비교 조건은 [점수 정책](SCORE-POLICY.md)에서 확인할 수 있습니다.

### 보고서 저장

1. 기록을 선택하고 **보고서**를 엽니다.
2. **보고서 양식**에서 종합·지능·성능·문항별 보고서를 선택합니다.
3. **테마**에서 라이트·다크·인쇄용을 고릅니다. 화면에 보이는 보고서가 저장 대상입니다.
4. **저장** 버튼을 누르고 형식을 선택합니다.

| 저장 형식 | 저장 범위 |
|---|---|
| PNG·SVG | 현재 보고서 페이지 |
| HTML | 전체 보고서 페이지 |
| PDF | 브라우저 인쇄 창에서 **PDF로 저장** 선택; 전체 페이지 |
| 원본 기록 JSON | 개인 보관·가져오기용 원시 기록 |

종합 보고서에는 점수와 장비 사양·사용률·온도·전력·시험 조건이 포함됩니다. 시험 이력은 **시험 기록 관리**에서 휴지통으로 옮기거나 복원할 수 있습니다.

## 평가 영역

| 평가 용도 | 출처 |
|---|---|
| 수학 추론 | GSM8K·MATH-500 |
| 지식·추론 | MMLU-Pro |
| 복합 논리 추론 | BIG-Bench Hard |
| 지시 이행 | IFEval |
| 코딩 | HumanEval·MBPP |

작은 시간 모드의 문항은 큰 모드에 포함됩니다. 8시간 모드는 위 영역 전체를 평가하는 선별 문항으로 구성됩니다. BBH는 별도 정확도로 표시합니다. LiveCodeBench는 재배포 조건 확인이 남아 별도로 설치합니다.

문항 구성과 실측은 [기본팩 안내](docs/BASIC-PACK.md), 원본 문항 수·출처·채점 방식은 [데이터 문서](datasets/README.md)에서 확인할 수 있습니다.

GSM8K 1,319 · MATH-500 500 · MMLU-Pro 12,032 · BIG-Bench Hard 6,511 · IFEval 541 · HumanEval 164 · MBPP 500문항으로 구성됩니다.

앱을 종료한 뒤 ZIP의 `datasets/full-bench-v1.json`을 앱의 `datasets/` 폴더에 복사하고 다시 실행하면 **전체 원본 벤치팩**을 선택할 수 있습니다. 자세한 순서는 ZIP의 `INSTALL.md`에 있습니다. 사용자팩 가져오기 버튼 대신 파일 복사로 설치합니다.

전체팩에는 10분·1시간·4시간·8시간 보정이 적용되지 않습니다. 기존 채점 규칙과 자료 결함 처리(BBH 5문항 채점 제외)는 유지합니다.

## 채점 방식과 측정 기준

벤치별 공식 프롬프트·정답·채점기를 기준으로 평가합니다. 적용 방식과 차이는 [데이터 문서](datasets/README.md)에 정리했습니다.

- **TTFT:** 요청 시작부터 가시 답변 첫 텍스트까지. 추론 첫 도착 시각은 별도 보관합니다.
- **Decode:** 서버 내부 속도와 클라이언트 가시 출력 속도를 구분합니다. 성능 점수는 후자를 사용하며 숨은 추론 토큰은 제외합니다.
- **Prefill:** 서버가 제공한 값만 표시합니다. API가 제공하지 않으면 미수집입니다.
- **Throughput:** 완료 응답 토큰과 전체 처리 시간으로 계산합니다. 단일 사용자 속도와 동시 요청 처리량을 구분합니다.
- **장비:** GPU·CPU·메모리 사용 상태와 온도·전력 등을 기록합니다. GPU 전력은 해당 카드의 측정값이며 서버 전체 소비전력과 다릅니다.

환경 실패·요청 오류·출력 잘림·오답을 구분하며 환경 실패를 오답 0점으로 바꾸지 않습니다. 저장된 답안을 재채점할 때 모델을 다시 호출하지 않으며 이전 채점 이력도 보존합니다.

## 자주 겪는 문제

| 증상 | 확인할 내용 |
|---|---|
| 시작 파일을 눌러도 실행 파일이 없다고 나옴 | 아래 소스 빌드를 진행하고 `bin/` 폴더에 실행 파일이 있는지 확인합니다. |
| 브라우저가 열리지 않음 | 시작 터미널을 확인하고 `http://127.0.0.1:18760`을 직접 엽니다. |
| 모델 연결 실패 | API 서버 실행 여부, 주소·포트·모델 ID·키·API 방식을 확인합니다. 외부 서버의 `127.0.0.1`은 벤치 PC의 localhost가 아닙니다. |
| 채점 준비 필요 | 해당 과목의 Python·NLTK 또는 Docker 준비 스크립트를 실행한 뒤 상태를 다시 확인합니다. |
| 장비 미연결 | 모델 서버에서 수집기가 실행 중인지, 수집기 URL·전용 토큰·접근 경로가 맞는지 확인합니다. |
| Prefill·온도·전력이 비어 있음 | API나 센서가 해당 값을 제공하지 않을 수 있습니다. 누락값을 추정해 표시하지 않습니다. |
| 성능·종합이 미산출 | 품질 문항의 TTFT·Decode 수집 상태와 지표 제외 사유를 확인합니다. 유효 측정값이 확보되면 자동 표시되며, 종합에는 지능 점수도 필요합니다. |
| 지능·종합이 범위로 나옴 | 미설치·미측정 평가 영역을 확인합니다. 앱 오류와 구분됩니다. |
| PDF 저장 창이 안 열림 | 브라우저의 인쇄 팝업 허용 상태를 확인하고, HTML 또는 PNG·SVG 저장도 사용할 수 있습니다. |

## 기록 위치와 백업

| 실행 방식 | 기본 데이터 폴더 |
|---|---|
| Mac | 앱 폴더의 `data/` |
| Windows 준비·시작 스크립트 | `%LOCALAPPDATA%\LLM-Bench\data` |
| 별도 경로 지정 | `BENCH_DATA_DIR` 또는 Windows 시작 스크립트의 `-DataDirectory` 값 |

앱을 종료한 뒤 **데이터 폴더 전체를 백업**하세요. 실행 중 백업이 필요하면 SQLite backup 방식을 사용합니다. 업데이트할 때도 데이터 폴더를 보존하세요.

연결 키는 데이터 폴더의 `credentials.json`에 저장됩니다. 데이터 폴더 백업에는 연결 키가, 원본 JSON에는 문제·답변·내부 주소가 포함될 수 있으므로 공유 전 확인하세요.

## 소스에서 빌드하기

이 절은 **GitHub 소스 또는 소스 ZIP**을 받은 경우입니다. 명령은 저장소 루트에서 실행합니다. Rust/Cargo와 Node.js/npm, 선택한 Rust 도구 체인에 맞는 C/C++ 빌드 환경이 필요합니다. 일반 채점에는 Python 3.11 이상, 코드 채점에는 추가로 Docker 환경이 필요합니다.

### Apple Silicon Mac

```bash
cd web
npm ci
npm run build
cd ..
cargo build --release --locked
mkdir -p bin
cp target/release/llm-bench bin/llm-bench
zsh packaging/Setup-Graders.command
zsh packaging/Start-Homelab-Bench.command
```

최초 준비를 나중에 하려면 마지막 명령을 `BENCH_SKIP_SETUP=1 zsh packaging/Start-Homelab-Bench.command`로 실행할 수 있습니다. Python 경로를 직접 지정하려면 준비 명령 앞에 `BENCH_SETUP_PYTHON=/실제/Python/경로`를 설정합니다.

### Windows PowerShell

```powershell
Set-Location web
npm ci
npm run build
Set-Location ..
cargo build --release --locked
New-Item -ItemType Directory -Force bin
Copy-Item target\release\llm-bench.exe bin\llm-bench.exe -Force
.\packaging\Setup-Graders-Windows.cmd
.\packaging\Start-Homelab-Bench-Windows.cmd
```

준비를 건너뛰고 내장 과목부터 실행하려면 `.\packaging\Start-Homelab-Bench-Windows.cmd -SkipSetup`을 사용합니다. 기록 폴더나 포트를 바꾸려면 `-DataDirectory 'D:\LLM-Bench-Data' -Port 18762`처럼 지정합니다. 명령 실행이 실패하면 다음 단계로 진행하기 전에 해당 오류를 해결하세요.
